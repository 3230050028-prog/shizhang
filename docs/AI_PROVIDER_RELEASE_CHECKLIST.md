# AI 模型接入：问题复盘与防错清单

## 一句话理解核心流程

用户在网页选择模型并填写 API Key 后，请求会依次经过：

1. **React + TypeScript 网页**：显示服务商和模型，收集用户选择。
2. **Supabase Edge Function**：验证登录状态，加密 API Key，并负责调用模型。
3. **PostgreSQL 数据库**：保存加密后的配置，并用约束限制允许的服务商。
4. **模型服务商 API**：真正回答问题，例如阿里云百炼的通义千问。

这四层像四道门。新增服务商时，只改其中一两道门，用户就会在下一道门被挡住。

## 这几次具体出了什么问题

### 1. 模型下拉框为空

- **现象**：选择通义千问后，页面提示没有可用模型。
- **原因**：网页依赖云端读取模型目录；云端尚未同步时，页面没有备用目录。
- **修复**：网页内置千问的可选模型，云端目录暂时不可用时仍能选择。

### 2. 提示“不支持这个模型服务商”

- **现象**：网页能选择千问，但保存时被拒绝。
- **原因**：GitHub Pages 前端已经更新，Supabase Edge Function 仍是旧版本。前端认识 `qwen`，云端函数还不认识。
- **修复**：重新部署 Edge Function，并回读线上源码确认 `qwen` 已存在。

### 3. 提示“AI 服务发生未知错误”

- **现象**：模型和密钥都已填写，保存仍失败。
- **原因**：数据库的 `provider` 检查约束仍只允许旧服务商，没有 `qwen`。数据库拒绝写入后，云端又没有正确提取数据库错误文字，所以页面只能显示“未知错误”。
- **修复**：更新数据库约束加入 `qwen`，同时让云端能显示数据库返回的真实错误。

## 为什么原来的测试没有发现

原测试分别确认了网页和 Edge Function 中存在 `qwen`，但没有核对数据库允许列表是否一致，也没有把“选择模型 → 保存配置 → 测试连接”作为一条完整线上流程验收。

现在增加了自动一致性测试：网页、Edge Function、初始数据库迁移和升级迁移中的服务商列表必须完全相同，否则测试直接失败。

## 新增或修改模型服务商时的发布顺序

1. 更新数据库迁移，并确认约束允许新的服务商 ID。
2. 部署 Supabase Edge Function。
3. 发布 GitHub Pages 前端。
4. 在线完成一次完整冒烟测试：
   - 服务商可选择；
   - 模型列表正常；
   - 配置可以保存；
   - “我的模型”出现新配置；
   - 测试连接成功；
   - AI 助手能回答一条不涉及敏感数据的测试问题。

## 每次发布前必须通过

- [ ] `npm test`：包括服务商允许列表一致性检查。
- [ ] `npm run lint`。
- [ ] `npm run build`。
- [ ] 数据库迁移已在线执行并回读结果。
- [ ] Edge Function 的线上版本包含本次修改。
- [ ] GitHub Pages 自动部署成功。
- [ ] 在用户真实打开方式中完成保存与测试连接。
- [ ] 日志和页面不显示、记录或回传完整 API Key。

只看到“代码上传成功”或“构建成功”都不代表功能已经可用；必须走完数据库、云端函数、网页和真实操作四层验证。
